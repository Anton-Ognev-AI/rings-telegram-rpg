# Phase 2B Checkpoint — Atomic Gameplay Commands

**Status:** `approved` locally on 2026-07-13. Gate 2C may start. No remote migration, Telegram call, or deployment occurred.

## Delivered

- Append-only signed XP ledger, cached account/cycle totals, daily cap 150, duplicate-source idempotency, partial cap awards, safe debits, and immutable reconciliation facts.
- Version-pinned runs, self/loadout snapshots, immutable stage results, one active run per player, typed HP/boss/stage/exchange/state-version constraints.
- SHA-256 prepared action tokens, immutable processed result cache, transactional outbox, and PII-key rejection for outbox/analytics JSON.
- Six `postgres`-owned, `security definer`, versioned public RPCs with `search_path = pg_catalog, game, pg_temp`: start, prepare, resolve, resume, begin deletion, and finalize deletion. Only `service_role` can execute them; it still has no private table access.
- Callback resolution accepts only token hash, Telegram update ID, actor UUID, and context hash. HP, XP, stage result, terminal state, and next state come only from the prevalidated prepared resolution.
- Cached replay happens before stale run-state checks but only after actor/context binding. A post-commit stolen or mismatched token therefore remains rejected.
- Narrow TypeScript `DatabasePort.call(...)` wrappers for start/prepare/resolve/resume and a local reconciliation command.
