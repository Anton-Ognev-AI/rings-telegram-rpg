## 0. Суть гри

Telegram-бот RPG у світі «Кільця Бога» (книги Антона). Щодня о фіксованій годині всі гравці отримують **один спільний «данж дня»** — згенерований LLM ланцюжок з 10 квестів наростаючої складності з виборами. Вибір — це прихований стат-чек; сервер кидає кубик. Провал закриває данж до завтра (здобич лишається). Прогресія: стати героя, предмети з рідкістю та магічні **грудні кільця** з багаторічною прокачкою. Соціалка: «пакт на день» з другом (взаємний бонус статів), лідерборд дня, шеринг emoji-результату.

---

## 1. Межі MVP

**У MVP входить:**
- Бот: онбординг, профіль, данж дня, пакти, лідерборд, налаштування часу сповіщення.
- Генерація данжа 1×/день (LLM) + Haiku-валідація + fallback-бібліотека.
- 1 картинка-обкладинка данжа/день (ADR 011).
- Стати, XP, предмети (3 слоти, 5 рідкостей), кільця (6 ступенів, стихії, есенція, прорив через боса).
- Пакт на день (+50% взаємно), стрік із заморозкою, шеринг-рядок, лідерборд дня.
- Server-side резолюція всього (ADR 012).

**У MVP НЕ входить (беклог):**
- Монетизація будь-яка (якщо колись — тільки косметика, ніколи не стат-чеки/лідерборд).
- Покроковий бій з босом (бос = квест з високими порогами).
- Картинка на кожен квест (після перевірки core loop).
- Кольорові гейт-квести («тільки для жовтого кільця+») — ідея №10 з ресерчу, v2.
- Ліги/тижневі когорти (актуально від сотень гравців), сезони, глобальні івенти.
- Анти-твінк перевірки пактів (вік акаунта ≥3 дні) — увімкнути при виході за коло друзів.
- Багатомовність (MVP — тільки українська), гільдії, ринок, крафт.

## 2. Принципи дизайну

1. **LLM оповідає — код рахує.** Модель генерує текст і теги; числа, кидки, нагороди — детермінований серверний код (ADR 012).
2. **Сервер — єдине джерело істини.** Клієнт (Telegram) надсилає лише вибір кнопки. Ідемпотентність на кожен крок.
3. **Один данж на всіх, персональні числа** (ADR 002). Пороги й нагороди скейляться під гравця.
4. **Канон книг понад ігрові вигадки.** Розбіжність → перевіряємо LORE_CONTEXT.md → рішення в DECISIONS.md.
5. **Ніякої провини в соціалці.** Пакт — бонус, не обов'язок; жодних «друг тебе чекає».
6. **Вартість під контролем.** Кешований лор-префікс, дешева модель на валідацію, 1 генерація/день.
7. **Числа живуть у config.** Усі балансові константи — в таблиці `config`, тюнінг без деплою.

## 3. Цикл дня (Europe/Kyiv)

| Час | Подія |
|---|---|
| 06:00 | pg_cron → `daily-generate`: генерація данжа → валідація → збереження → обкладинка |
| 06:20 | Якщо валідація двічі провалилась → fallback-данж з бібліотеки; алерт Антону |
| 09:00 (або слот гравця) | `daily-broadcast`: «Данж дня відкрито» зі стаггером ≤25 msg/s |
| 09:00–23:59 | Гравці проходять данж кожен у своєму темпі |
| 23:59 | Данж зачиняється; незавершені прогони фіксуються as-is |
| 00:05 | Підсумок дня: лідерборд, нарахування стріків |

Пропущений день без заморозки → стрік скидається (див. §10).

## 4. Данж, квести, вибори

### 4.1 Структура данжа
- **Тема дня** (1 рядок) + сюжетна рамка, що зв'язує квести.
- **10 квестів**: 1–3 легкі (небойові часто), 4–6 середні, 7–9 важкі, 10 — **бос дня**.
- Глибина 7+ збалансована під пакт (див. §9): соло дістатись боса важко, але можливо на високих статах.

### 4.2 Квест
- **Текст:** ≤700 символів (запас під caption-ліміт Telegram 1024).
- **2–4 варіанти**, кожен ≤40 символів (кнопки). Прихований тег варіанта: `{stat: str|agi|vit, tier: safe|easy|mid|hard, greed: normal|greedy}`.
- Типовий набір: жадібний (🔴 повна+бонусна нагорода), розумний (🟡 — треба вгадати з тексту, ЯКИЙ стат перевіряється), обережний (🟢 слабкий чек або `safe` — прохід без нагороди).
- **Пастки:** ≤1 на данж, ніколи на квестах 1–2: варіант виглядає обережним, але має чек. Вчить читати текст.
- **Стихійний варіант** (ADR 010): у 2–3 квестах данжа — 4-й варіант, доступний лише носіям кільця відповідної стихії; tier легший за аналогічний звичайний (перевага прокачки).
- Гравець бачить **іконку ризику** (🟢🟡🔴) на кожному варіанті — персонально розраховану з його статів. Чисел не бачить (патерн Reigns: значущість без калькулятора).

### 4.3 Резолюція чека (server-side)
```
effective(stat) = floor( (base_stat + items_stat) × (1 + ring_bonus_total) )
check_stat      = effective_self(stat) + 0.5 × effective_partner(stat)   // якщо пакт активний
chance          = clamp( 50% + (check_stat − threshold) × 5%, 5%, 95% )
roll            = random(0..100) на сервері
```
- `threshold = E_main(player_level) + Δ(tier)`, де `E_main` — таблична функція очікуваного «головного» стата гравця цього рівня, `Δ = {easy: −2, mid: +1, hard: +4, boss: +6}` (v1; фінал — після симуляції, §16).
- `safe`-варіанти чека не мають.
- Успіх → нагорода квесту (XP завжди; предмет/есенція за таблицею шансів) → наступний квест.
- Провал → данж закрито до завтра, все зібране лишається (ADR 004).

### 4.4 Зв'язність ланцюжка
Генератор отримує вказівку: квест N+1 легко посилається на результат N (патерн Reigns) — тематично, без механічної залежності. МVP-реалізація: у промпті данж пишеться як цілісна історія з наростанням.

## 5. Персонаж

- **Стати:** сила (str), ловкість (agi), живучість (vit) — три типи чеків. Живучість: отрути, витривалість, пастки.
- **Старт:** 5/5/5, рівень 1, порожні слоти, без кільця.
- **XP:** заробляється у квестах; вільний пул `xp_free`. Гравець вручну розподіляє з профілю: **+1 до стата** або **→ есенцію активного кільця** (1 XP = 1 есенція).
- **Рівень героя** = f(сумарно зароблений XP), таблиця порогів у config. Рівень керує скейлінгом порогів данжа і відкриває: **рівень 10 — другий слот кільця**.
- XP за квест i: `8 + 2×i` (10…26), бос: +60. Повний прохід ≈ 220 XP; середній день (5–7 квестів) ≈ 70–115 XP.

## 6. Кільця (ядро прогресії)

### 6.1 Канонічна рамка (ADR 008)
Ступені: **помаранчеве → синє → зелене → жовте → фіолетове → чорне**. Перші чотири — канон книг (помаранчеве — адепт, жовте — вершина Вчителя); фіолетове — «за межами відомого»; чорне — канонічна аномалія (кільце Макса), міфічний ендгейм. Стихія **незалежна** від ступеня (канон): вогонь, вода, лід, вітер, земля, світло, пітьма, простір (плоть — заборонена в каноні; у грі не дропається, зарезервовано під сюжетні івенти).

### 6.2 Отримання
- Кільце — **дроп з боса дня**. Стихія фіксується при дропі.
- Гравець без кільця: перший убитий бос **гарантовано** дропає помаранчеве кільце (випадкова стихія).
- Далі шанс дропа кільця з боса ≈ 8% (config) — друге кільце і заміни — рідкісна подія.
- Слоти: 1 (старт), 2 (рівень 10). **Конфліктні стихії** (вогонь+вода, світло+пітьма, вітер+земля — канон) в двох слотах разом носити не можна.
- Прийняти нове кільце поверх старого = старе розвіюється, **есенція не повертається** (v1; діалог підтвердження з показом втрати; % повернення — тюнінг у config).

### 6.3 Прокачка
- **Есенція** — окремий лічильник на кожне кільце; поповнюється конвертацією XP 1:1.
- **Бонус кільця:** відсотковий до всіх статів (тому кільце ефективніше за плоскі +1 — задум Антона):

| Ступінь | Бонус | Есенція до наступного | Орієнтир часу (~60 есенції/день) |
|---|---|---|---|
| Помаранчеве | +5% | 500 | ~тиждень |
| Синє | +12% | 3 000 | ~2 місяці |
| Зелене | +25% | 18 000 | ~10–12 місяців |
| Жовте | +55% | 108 000 | ~5 років |
| Фіолетове | +110% | 648 000 | легенда (десятиліття) |
| Чорне | +200% | — | вершина |

- Перевірка задуму: два зелених (7 000 есенції сумарно, +50%) — утричі дешевші за одне жовте (21 500, +55%), але жовте сильніше. ✓
- **Прорив ступеня** (ADR 009): повна есенція **+ перемога над босом дня** → наступного дня кільце нового кольору (анонс у підсумку дня). Канон: «прорив під напругою».
- Бонуси двох кілець додаються (+25% + +12% = +37%).

### 6.4 Стихія в геймплеї
Стихійні варіанти квестів (§4.2) — «одна техніка на кільце» з канону. Флейвор техніки в описі кільця у профілі (генерується один раз при дропі).

## 7. Предмети

- **3 слоти:** зброя (нахил у силу), броня (нахил у живучість), аксесуар (нахил у ловкість).
- **5 рідкостей** з бюджетом сумарних статів (v1): звичайний +1–2, незвичайний +2–4, рідкісний +4–7, епічний +7–11, легендарний +11–16. Розподіл між статами і назву генерує LLM у межах бюджету; числа валідує код.
- Дроп: таблиця шансів по глибині квеста (глибше = рідкісніше; бос — гарантований предмет ≥рідкісного).
- **Заміна (механіка Антона):** нагорода показує порівняння зі старим предметом слота → прийняв = старий зникає; відхилив = предмет втрачено. Без інвентаря-складу в MVP.

## 8. Бос дня

- Механічно — 10-й квест з порогами `boss`-tier і 2–4 тактиками (варіантами) + стихійні тактики.
- Нагороди: +60 XP, гарантований предмет ≥рідкісного, шанс кільця 8%, есенція-бонус (+20).
- Перемога — умова прориву ступеня кільця (§6.3) і топу лідерборда.

## 9. Пакт на день

- Інвайт: `/pact` → вибір друга (deep-link `t.me/<bot>?start=pact_<code>` для того, хто ще не в грі — це і є вірусна петля).
- Партнер прийняв → **обидва** до 23:59 отримують +50% ефективних статів одне одного (взаємність — ресерч Clash Royale, ADR 005 + ідея 12). Снепшот статів на момент активації пакту.
- Кожен грає **свій** прогін у свій час; синхронність не потрібна.
- Партнер не зайшов у гру — бонус все одно діє, жодних повідомлень про «втрату» (анти-FarmVille, ідея 13–14).
- Обидва пройшли ≥3 квести → обом «спільний трофей»: +15 XP (config).
- 1 активний пакт на день на гравця. Скасування — до першого кроку будь-кого з пари.

## 10. Retention

- **Стрік:** лічильник днів з ≥1 зіграним квестом. **1 заморозка/тиждень** авто-гаситься при пропуску (Duolingo, +14% D7 retention). Стрік ≥7 днів → +10% XP.
- **Шеринг:** після завершення прогону — готовий рядок: `🗡 Крипта Вальморів · ✅✅✅✅❌ 4/10 · 112 XP` — spoiler-free (Wordle-патерн), гравець сам пересилає.
- **Лідерборд дня:** глибина → очки → час; наше коло = природна «мала ліга» (ідея 15).
- **Баг-баунті:** перші місяці — внутрішньоігрова нагорода (есенція) за корисний репорт (Chat Wars Echo Orb).

## 11. Онбординг і меню

- `/start`: 2 коротких лор-повідомлення (світ + що таке грудне кільце) → герой створений (5/5/5) → якщо данж дня відкритий, кнопка «⚔️ Увійти в данж».
- Головне меню (reply-клавіатура): **⚔️ Данж дня · 🎒 Герой · 🤝 Пакт · 🏆 Лідерборд · ⚙️ Налаштування**.
- «🎒 Герой»: стати, вільний XP (кнопки розподілу), кільця (ступінь/стихія/есенція/техніка), предмети, стрік.
- «⚙️»: час сповіщення (слоти по 30 хв, дефолт 09:00), вимкнути сповіщення.

## 12. Генераційний pipeline

### 12.1 Генерація данжа (Sonnet-клас, 1×/день)
- **Промпт:** [кешований префікс: лор-канон + правила формату] + [тема-сід дня + вимоги різноманіття від учорашніх тем].
- **Structured output (JSON):**
```json
{
  "theme": "Крипта Вальморів",
  "cover_prompt": "опис сцени для обкладинки",
  "quests": [
    {
      "idx": 1,
      "text": "≤700 символів",
      "options": [
        {"label": "≤40 симв", "stat": "agi", "tier": "mid", "greed": "greedy"},
        {"label": "...", "stat": "str", "tier": "easy", "greed": "normal"},
        {"label": "...", "stat": null, "tier": "safe", "greed": "normal"},
        {"label": "...", "stat": "vit", "tier": "easy", "element": "fire"}
      ]
    }
  ]
}
```
- LLM **не** пише числа порогів/нагород — лише теги. Числа мапить код (§4.3, §15).

### 12.2 Валідація (Haiku-judge)
Схема (zod) + перевірки: довжини, рівно один данж-масив на 10, теги з дозволених enum, немає двох `safe` в одному квесті, чек безпечності контенту, узгодженість мови (укр., без русизмів). Провал → 1 retry з фідбеком → провал → fallback.

### 12.3 Fallback-бібліотека
≥7 заготовлених данжів (пишуться під час розробки цим же pipeline + ручне рев'ю). Ротація за датою, позначка `fallback` у підсумку дня для телеметрії.

### 12.4 Обкладинка (ADR 011)
1 картинка/день з `cover_prompt` + **фіксований стиль-суфікс** (config) для консистентності. Модель — обрати на імплементації (gpt-image / Flux via API — за ціною/якістю). Фейл генерації → данж іде без картинки (не блокер).

### 12.5 Вартість (оцінка)
Генерація ~$0.05–0.15/день + валідація <$0.01 + 1 картинка ~$0.02–0.06 → **$3–7/міс**. Запас до бюджетного орієнтира $10–20/міс — на експерименти.

## 13. Модель даних (Supabase Postgres)

| Таблиця | Ключові поля |
|---|---|
| `players` | tg_id PK, name, str, agi, vit, xp_free, xp_total, level, streak, freeze_used_week, notify_slot, created_at |
| `rings` | id, player_id FK, slot (1/2), element, tier, essence, technique_flavor, created_at |
| `items` | id, player_id FK, slot (weapon/armor/accessory), rarity, str, agi, vit, name |
| `dungeons` | date PK, theme, payload jsonb (§12.1), cover_url, source (llm/fallback), created_at |
| `runs` | id, player_id FK, dungeon_date FK, depth, xp_earned, state (active/failed/completed), pact_id NULL |
| `run_steps` | run_id FK, quest_idx, option_idx, roll, success, reward jsonb, ts — **UNIQUE (run_id, quest_idx)** (ідемпотентність) |
| `pacts` | id, date, player_a, player_b, status (invited/active/cancelled), snapshot_a jsonb, snapshot_b jsonb |
| `fallback_dungeons` | id, payload jsonb, last_used date |
| `config` | key PK, value jsonb — всі балансові константи (§15) |

Лідерборд дня — view по `runs` за датою. RLS мінімальна: доступ лише через service role Edge Functions (клієнтських підключень немає).

## 14. Архітектура

- **Edge Functions (Deno):**
  - `tg-webhook` — grammY: команди, кнопки (callback_data ≤64 байт: `q|<idx>|<opt>`, `xp|str`, `pact|acc|<id>`…), меню.
  - `daily-generate` — cron 06:00: генерація → валідація → збереження → обкладинка.
  - `daily-broadcast` — cron кожні 30 хв 09:00–21:00: сповіщення гравцям слота, стаггер ≤25 msg/s.
- **pg_cron + pg_net** — розклад; секрети в Supabase Vault/env.
- **Telegram-ліміти:** caption ≤1024 (наш текст ≤700 + запас), 4096 для текстових, callback 64 байти, ~30 msg/s broadcast.
- **Стан** — лише в БД (functions stateless). Подвійний клік по кнопці → UNIQUE-конфлікт → повтор попередньої відповіді.
- Алерти (генерація впала, fallback задіяно) — повідомлення Антону в Telegram.

## 16. Тестування і верифікація

1. **Юніт:** формула шансу, мапінг tier→поріг, економіка XP/есенції, конфлікти стихій, ідемпотентність кроку.
2. **Симуляція балансу (до релізу):** скрипт Monte-Carlo «N профілів × 1000 днів»: перевіряє орієнтири часу ступенів (§6.3), властивість «два зелених швидші/слабші за жовте», відсутність глухих кутів (гравець, що не може пройти квест 4 на своєму рівні).
3. **Схема-тести генерації:** 20 прогонів `daily-generate` на тест-проєкті → 100% валідних JSON після retry.
4. **E2E:** тестовий бот + фіксований данж: повний прогін, пакт, провал, підсумок.
5. Ручний плейтест кола друзів ≥1 тиждень перед розширенням.

## 17. Відкриті питання (не блокують імплементацію)

1. **Назва гри / нік бота** — потрібна до публічного тесту.
2. Image-модель для обкладинок — обрати на фазі імплементації порівнянням 2–3 варіантів.
3. Фінальні числа балансу — після симуляції (§16.2).
4. Git: репозиторій ще не ініціалізований — зробити на старті імплементації (перший коміт = ця спека).

## 18. Порядок імплементації (ескіз для плану)
